## Verified production definitions
- public.is_shop_staff: active staff and private.is_staff_business_session_current; latter checks auth.sessions ID/user and 08:00 JST cutoff. New routes additionally require not retired.
- private.registered_card_store_scope: super_admin all; store_admin assigned active store; staff denied. Existing note RPC uses this scope even without directory grant. Preserve existing note route; candidate unified write requires directory grant.
- private.staff_directory_points_access_v1: super_admin or store_admin with active matching directory_point_grants; active and not retired.
- private.manage_card_directory_points_v1: matching active card, no replacement, store_admin issue-store scope and operation store for visit/checkout; lock profile and grant. Existing checkout core request_id support is not the new R24 confirmation/receipt protocol.
- public.staff_card_details_v3 and staff_prepared_card_status: token hash lookup; no directory grant requirement. These are not substitutes for a server-authorized directory ID. Existing staff scan rights must not be lost or widened. Real scan path requires separate server identity validation and route-specific operation RPC. Never derive permission from the frontend or card number.
- Existing scan visit/checkout core accepts active operation store; new draft limits to assigned store (except super_admin) pending policy review, so DO NOT activate this restriction in production without deciding cross-store staff behavior. Legacy memo endpoint has no version check; R32 must include shared version trigger to catch legacy writes too.
